# 출연 섹션 설계

- 날짜: 2026-10-02
- 상태: 승인됨

## 목표
"함께한 기업"과 나란히 **출연** 섹션을 만든다. 리센느가 출연한 유튜브 채널·웹예능, TV 예능, 라디오, 음악방송을 팬들이 함께 기록한다.
사이트 이름 "리센느 계열사"는 유지하고, 메인의 주인공은 계속 기업이다.

## 결정 사항
| 항목 | 결정 |
|---|---|
| 사이트 내 위치 | 기업과 별도인 '출연' 섹션 |
| 문서 단위 | 채널·프로그램 하나 = YAML 파일 하나. 출연 회차는 `media` 목록 |
| 포함 종류 | 유튜브·웹예능, TV 예능, 라디오, 음악방송 |
| 구현 방식 | 별도 컬렉션 `appearances` (기업 컬렉션은 건드리지 않음) |

## 1. 데이터 구조
위치: `src/content/appearances/<영문-슬러그>.yaml`

| 필드 | 필수 | 설명 |
|---|---|---|
| `name` | O | 프로그램·채널 이름 |
| `summary` | O | 한두 문장 요약. 확인 안 된 내용은 `확인필요`라고 적는다 |
| `category` | O | `유튜브·웹예능` / `TV 예능` / `라디오` / `음악방송` |
| `broadcaster` | | 방송사나 채널 운영자 |
| `website` | | 프로그램·채널 공식 주소 |
| `sources` | O | `{title, url}` 1개 이상 |
| `media` | | 기업 문서와 같은 형식(`kind`, `platform`, `url`, `title`, `orientation`, `date`). 기본값 `[]` |

- `media` 항목 스키마는 `src/content.config.ts`에서 공통 상수로 뽑아 두 컬렉션이 함께 쓴다. 기업 데이터의 형식은 바뀌지 않는다.
- `type`, `status`, `startDate`, `endDate`는 없다. 최근 출연일은 `media[].date` 중 최댓값으로 계산한다.
- 출연 멤버 필드는 두지 않는다(YAGNI). 필요하면 회차 제목에 적는다.

## 2. 페이지와 메뉴
- **`/appearances/` 출연 목록**: 기업 목록과 같은 카드 그리드. 카드에는 커버 썸네일, 종류 배지, 방송사, 최근 출연일, `영상 N개`가 들어간다. 검색창과 종류 칩 필터(전체 + 데이터에 있는 종류)를 둔다. 정렬은 최근 출연일 내림차순이고, 날짜가 없는 문서는 뒤로 간다.
- **`/appearances/[slug]/` 출연 상세**: 기업 상세와 같은 레이아웃. 제목, 배지, 요약, 방송사·공식 링크, `✏️ 이 문서 편집`이 들어간다. 회차 영상은 날짜 최신순이고 맨 아래에 출처를 둔다. 뒤로가기는 `← 출연 목록`이다.
- **헤더 메뉴**: 맨 앞에 `기업`, `출연` 링크를 추가한다.
- **메인**: 통계에 `출연 N`을 추가한다. 기업 목록 아래에 최근 출연 3개 카드와 `출연 전체 보기 →`를 둔다.
- **문구**: 메인 설명, 소개 페이지, README를 "리센느와 함께한 기업과 출연 프로그램"으로 넓힌다.
- **코드**: `src/lib/appearances.ts`의 `getAppearances()`가 정렬, 최근 출연일, 커버를 계산한다(`sponsors.ts`와 같은 패턴). 카드 마크업은 페이지별로 두고 공통 컴포넌트로 합치지 않는다. 검색·필터 스크립트는 기업 목록의 방식을 재사용한다.

## 3. 제보 흐름
- 새 이슈 양식 `.github/ISSUE_TEMPLATE/new-appearance.yml`: 이름, 종류(드롭다운), 방송사, 출연 영상 링크, 출처 링크(필수), 메모. 라벨은 `제보`.
- `add-media.yml`의 대상 문서 설명을 "기업 또는 출연 문서"로 바꾼다.
- `CONTRIBUTING.md`에 "새 출연 추가하기" 항목과 규칙을 추가한다. 규칙은 **방송사·채널 공식 업로드만 넣고, 팬 재업로드나 짜깁기 영상은 넣지 않는다**이다.
- README 표에 "새 출연 추가하기" 줄을 추가한다.
- 헤더의 `기업 제보` 버튼은 유지한다. 출연 제보 링크는 출연 목록 페이지와 "결과 없음" 안내에 둔다.

## 4. 첫 데이터
- 기사와 공식 채널 원문으로 출연 사실과 날짜를 확인한 것만 넣는다. 영상은 공식 업로드만 쓴다. 나무위키는 단서로만 쓰고 출처로 적지 않는다.
- 확실한 것 위주로 10곳 안팎을 넣고, 종류별로 고르게 담는다.
- 음악방송은 프로그램마다 대표 무대 몇 개만 넣는다.

## 5. 검증
- `npx astro check`와 `npm run build`가 통과해야 한다(CI `check` 작업과 같다).
- 출처가 없는 임시 YAML로 스키마가 실패하는지 확인한 뒤 지운다.
- 로컬에서 확인할 것: 목록과 상세 페이지, 종류 필터와 검색, 메인의 최근 출연 3개, 사이트맵에 출연 페이지 포함 여부.
- 배포한 뒤 `https://remine.fan/appearances/`를 확인한다.

## 범위 밖
- 방문자 수 표시(보류)
- 회차 단위 문서, 출연 멤버 필드
- 기업과 출연을 합친 공통 컬렉션으로의 재구성
